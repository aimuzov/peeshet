## Правила

- Голос мой: черновик пишется по брифу `mcp__thinks__write_as_me` (register `longform`).
  `check_as_me` гоняется только по прозе абзацев (без заголовков, разметки списков, таблиц и
  ссылок), цель для лонгридов от 85; штраф за длину ожидаем.
- Посты длинные и с пояснениями, везде rich Markdown (Telegram Rich Messages):
  - девлог — короткая статья: вводный абзац (зачем это читателю и что изменилось), разделы `##` по
    проекту или теме, в них буллеты с объяснением простыми словами и ссылкой на PR, коммит или
    релиз у каждого изменения; сравнение нескольких вещей оформляй таблицей;
  - разбор — полный лонгрид: зачем, какие были варианты, код, таблицы, картинки;
  - релиз — что нового для читателя и ссылка на релиз;
  - мысль и неделя — как подходит по смыслу, те же средства разметки.
- Фото стоят отдельным абзацем там, где нужны по смыслу: `![](tg://photo?id=p1 "подпись")`.
  Ключ `p1` выдаёт загрузка картинки в очередь.
- Ссылки только на ПУБЛИЧНЫЕ репозитории. Видимость проверяй
  `gh repo view <owner>/<repo> --json visibility`; приватные проекты описываем без ссылок.
  Ссылки на живые сайты и бота можно везде.
- Факты берём из `gh search prs --author @me --merged --merged-at ">=YYYY-MM-DD"`, git log,
  changelog и моих слов. Не выдумываем цифры, планы и оценки.
- Хэштег рубрики — последняя строка, пишется экранированным: `\#девлог` (иначе Telegram
  рисует заголовок). Один на пост. Имя проекта пишем текстом, хэштег не нужен.
- Кастомных эмодзи нет. Обычные только из моей палитры (👋 ✅ ⏳ ❤ 😶 🎒) и редко.
- Картинки нужны для релизов и разборов. Девлог можно без картинки, лучше со скриншотом.
